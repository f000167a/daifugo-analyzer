# 大富豪 勝率シミュレータ

初期手札から、簡略ルールと固定AIの下での各順位への着地割合をモンテカルロ法で推定するシングルファイルWebアプリ。実際の対人勝率や最適戦略を保証するものではない。

---

## 使い方

`index.html` をブラウザで開くだけで動作する。サーバー・インストール不要。

1. **設定**でプレイヤー人数・現在の役職・ルールを選択
2. **手札入力**で各数字の所持枚数を入力（ランダム配布ボタンで試せる）
3. **分析する**を押すと2000試行のモンテカルロシミュレーションが走る
4. 各順位への推定確率・役職別アドバイス・手札別戦術ポイントが表示される

人数と「自分の枚数」に合わない入力は計算前に案内される。ランダム配布は選択した枚数を使う。計算中は「計算を中止」で止められ、手札・人数・役職・ルールを変えたときは実行中の計算と古い結果を取り消す。変更後は再度「分析する」を押す。

---

## 設定項目

### プレイヤー人数
3人・4人・5人から選択。役職名と手札枚数が自動で切り替わる。

| 人数 | 役職構成 | 手札枚数 |
|------|---------|---------|
| 3人 | 富豪・平民・貧民 | 18枚固定 |
| 4人 | 富豪・平民・平民・貧民 | 13枚 or 14枚（選択可） |
| 5人 | 富豪・平民・平民・平民・貧民 | 10枚 or 11枚（選択可） |

4人・5人は余りカードが生じるため、自分の手札枚数をセレクタで選択できる。

### 現在の役職
アドバイス表示と都落ちルールの適用に使用。2回目以降のゲームでは実際の役職を選ぶ。

| 選択肢 | 説明 |
|--------|------|
| 平民（初戦） | 全員フラットな状態 |
| 富豪 | 前回1位。1位以外は都落ちで最下位確定 |
| 平民 | 前回中位。都落ちなし |
| 貧民 | 前回最下位。都落ちなし |

入力する手札は**カード交換後の状態**を想定して入力する。

### ルール設定
- **8切り**：8を出すと場がリセットされ手番が継続する
- **革命**：同じ数字4枚出し（またはジョーカー補完）で強弱が逆転する
- スペード3返しなし・ジョーカー2枚は固定

## シミュレーションのしくみ

### モンテカルロ法（2000試行固定）

1. 入力した手札を自分（プレイヤー0）に固定
2. 残りのカードをシャッフルして他プレイヤーへ配布。全員が人数に対応する枚数を持ち、余りは別々の相手へ1枚ずつ割り当てる。多く持つ相手の席も毎回無作為に選ぶ
   - 4人：全体で13枚×2人、14枚×2人
   - 5人：全体で10枚×1人、11枚×4人
   - デッキ54枚を重複・欠落なく使用。先手は各プレイヤーから一様に選ぶ
3. 全プレイヤーがAIで1ゲームを完了させ、自分の順位を記録
4. 1〜3を2000回繰り返し「1位になった回数 ÷ 2000」などを確率として表示

**試行のばらつきの目安**：各順位について、独立試行の二項比率の標準誤差は `sqrt(p(1-p)/2000)`。最大となる `p=0.5` では約1.1パーセントポイント、95%の正規近似の半幅は約2.2ポイントになる。表示値が0%や100%でも、不可能・確実という意味ではない。順位ごとに丸めるため合計が100%にならない場合がある。

これは同じモデルを繰り返したときの標本誤差の目安であり、AI・ルール・配布仮定の正しさや対人戦の予測精度を検証するものではない。カード交換後の手札を入力するが、交換によって生じる相手の手札の偏りはモデル化しない。

### 都落ちルール
- 自分が富豪で1位以外に終わると最下位確定
- シミュレーション内でも同様に処理される
- 平民（初戦）・平民・貧民の入力では着順補正をしない
- 相手の役職は入力されていないため、特定の相手を前回富豪と仮定した繰り上げは行わない

### AIの戦略ロジック（pick関数）

全プレイヤーが同じ評価関数で動く。評価項目は以下。

**基本戦術**
- 手牌を使い切る手に加点（コンボ処理優先）
- 場なし時：通常は弱いカードから出してリズムを作る。残り5枚以下・危険時は強いカード優先
- 場あり時：ちょうど1〜3ランク上の手が理想。大きく上回る手は温存
- 相手の残り枚数が3枚以下（danger）・5枚以下（urgency）で強カード投入に切り替え

**革命先読み**
- 4枚組またはジョーカー補完の革命候補を持っている場合、革命後に弱くなるカード（2・A・K等）を事前に優先して切る
- 革命を出す前に「革命後の残り手の平均強度」を計算し、強いほど革命を選びやすくなる
- ジョーカーを革命補完に使う予定があれば単体出しを抑制

**ジョーカー（ワイルドカード）**
- 場への応答・親出しのどちらでもペアやトリプルの補完に使用可能（例：K×1+JKRでK×2扱い）
- 3枚組+JKRで革命成立（K×3+JKRなど）
- 残り枚数・危険度・革命候補の有無で単体出しか補完かを判断

**制約**
- AIは心理・ブラフ・記憶を持たない
- 全員が同じ評価関数で動く（プレイスタイルの差なし）
- 確率はこのAIどうしが戦うモデルでの標本推定値。理論的な勝率・対人勝率ではない
- AIは合法な候補から評価関数で手を選ぶが、最適性の保証はない
- 通常画面では非表示の実験用強化モードは、相手の手札も知った状態の決定的な先読みであり、不完全情報のMCTSではない。同一局面の展開を反復しても結果は同じなので1回だけ計算する。通常モードの2000試行と区別して150試行で動作する

## 分析結果の読み方

### 各順位の確率
- **1位率**が最も重要な指標
- 富豪は1位率のみ参照（2位も都落ちで最下位と同じ）
- 貧民は最下位回避率（`100 - 最下位%`）を参照

### アドバイスボックス

| ボックス | 内容 |
|---------|------|
| 役職別アドバイス | 役職ごとの確率帯に応じた立ち回り方針 |
| 手札別の戦術ポイント | 革命候補・ジョーカー・ペア・8切りなど手札構成に基づく具体的な戦術 |
| 確率の読み方 | 1位確率帯ごとの解釈と注意点 |

## ファイル構成

```
index.html   すべてのHTML・CSS・JSを含む単一ファイル
README.md    本ドキュメント
train.py     任意の係数学習用Pythonスクリプト（NumPyが必要）
tests/       回帰テスト（アプリを開く際は不要）
```

外部依存はGoogleフォント（Noto Sans JP・JetBrains Mono）のみ。オフライン環境ではシステムフォントにフォールバック。

## 固定ルール・仕様

- デッキ：通常52枚＋ジョーカー2枚＝54枚
- ジョーカーは通常時・革命時とも最強（スペード3返しなし、ジョーカーでジョーカーは返せない）
- ジョーカーのみは単体出し。自然カードと組み合わせるときは同じ数字の2〜4枚組を補完する
- 革命：同一数字4枚出しで強弱逆転（ジョーカーによる補完も可）
- 8切り：8を出した瞬間に場がリセット、手番が継続
- 縛り：同数の枚数しか出せない（ペア縛りなど）
- 上がり：手札を全て出した時点で順位確定、場がリセット
- パス後に他の人がカードを出した場合は、次の自分の手番で再び出せる。連続して他の全員がパスすると場がリセットされ、最後に出した人から続ける
- 手番上限に達した未完了の試合はエラーにし、残りの席順を順位として採用しない

## テスト

アプリ本体は引き続き `index.html` だけで動作する。テストは実際のインラインJavaScriptを読み込み、外部のテスト用ゲームエンジンを使わない。

```sh
node --test tests/*.test.cjs
python -m unittest discover -s tests -p test_training.py -v
```

Node.jsの組み込みテストランナーを使用する。Python側は任意の学習スクリプト用で、NumPyが必要。

- 固定seedで3/4/5人・両方の手札枚数・8切り/革命の各設定を検証
- 配布54枚の保存、各数字の上限、全手の合法性、消費枚数、手番、上がり・終了を確認
- ジョーカーの強さ、同じ枚数の制約、補完出し、都落ち適用の回帰テスト
- UIのDOM/タイマーハーネスで入力エラー、中止、連打、設定変更、例外復帰、結果の設定スナップショットを確認
- DOMハーネスはブラウザの見た目・タッチ操作・描画速度を保証しない。実ブラウザ確認は別途必要

既存の評価係数は変更していない。ルール・実装の整合性を確認するテストであり、戦略の強さを比較するベンチマークや再学習ではない。
